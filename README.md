# 认证审核计划辅助系统

根据参考文件生成管理体系审核计划初稿，支持部门分工、条款拖拽、专业能力检查和日程预览。

## 在线使用

https://haizhouwang2025-jpg.github.io/audit-plan-assistant/

直接打开页面，将审核任务通知书拖入“导入审核任务通知书”区域，或点击选择文件。支持 `.doc`、`.docx`、带文字层的 PDF；系统先打开复核页，确认前不改变原计划。补充实际部门及承担过程、复核专业能力和时间安排后，点击“确认并重排”。

配套 `.xlsx` 仍可从同一入口导入。审核员继续填写原表 `Sheet1`，程序优先读取隐藏的 `Sheet2_小程序读取`。

## 功能

- 支持 QMS、EMS、OHSMS 单体系及其组合。
- 机构适配：海德和中标联合（北京）认证有限公司均支持 Q/E/S 单体系、二体系和三体系组合。通知书按机构名称、域名、表单编号或海德既有字段结构识别，复核页显示机构及输出模板，允许人工改选。无法匹配或出现冲突时，不自动套用海德。
- 中标联合按通知书 NSI/CX-01-02 读取项目编号、分体系范围和准则、人员、注册状态、文审职责、专业代码、总人日及现场人日；保留专业代码后缀。输出使用 NSI/CX-01-04 原生 Word 模板。专业代码未明确体系时不自动授予跨体系专业能力；注册状态为专家或实习的人员不作为对应体系的独立审核员。其他机构及 Q/E/S 以外的体系仍须单独适配。
- 根据 Excel 实际填写的体系范围自动识别单体系、二体系或三体系，联动更新标题、条款、审核员专业选项、覆盖检查及日程。配套表的 Sheet1 实际范围优先于旧隐藏页中固定的 QES 值；空白或“不适用”的范围不计入体系。无法识别时保留原计划并提示，不默认按单Q处理。
- 系统界面使用 Apex Nexus Technology 标志，名称为“认证审核计划辅助系统”；保留现有红色操作按钮及各类检查状态颜色。输出计划的机构标识由对应模板决定，不使用系统品牌替换认证机构名称。
- 按实际部门合并多个过程，同部门、同体系条款去重。
- 按体系专业能力生成分工建议，支持技术专家共同审核。
- 通过拖动条款卡片调整部门分配，同步更新覆盖检查和日程。
- 新增部门后可直接选择条款；已有部门可从条款工具按钮重新选择。支持按体系、条款号或名称筛选。同一条款可保留在多个部门，每个部门内只出现一次，专业能力检查仍然生效。
- 分别保留当前页面内的一、二阶段调整。
- 缺省标准为 Q：GB/T 19001-2016/ISO9001:2015；E：GB/T 24001-2016/ISO14001:2015；S：GB/T 45001-2020/ISO 45001:2018。通知书或 Excel 未填写时自动补齐，不要求每个项目重复填写；明确指定其他版本时保留原值，组长可修改。EMS 条款库随准则版本切换，不能只更改输出文字；当前支持 2015、2026 两个版本，其他明确但未支持的版本需进一步适配。
- 通知书复核包含项目资料、审核组、部门过程、午休、倒班及指定人员的场所间转场。缺失或有冲突的内容由组长核对，不以演示数据替代。相同实际部门的多个过程会归集。
- “添加场所审核”可填写场所、往返日期与时间，勾选参与人员及审核部门。到达后、返程出发前安排该场所的部门任务；只有所选人员的路途和外出时段被占用，其他人员继续原场所审核。每条场所安排单独校验独立主审和专业覆盖，不以其他场所人员的能力代替。
- 审核组信息从通知书“审核组长、审核组成员及与审核组同行的人员”表格关联读取，包括身份、证书、分体系专业代码、单位、专职情况和电话。支持单元格内多段文字及常见专业代码写法；无法可靠识别的内容仍须复核，不以注册体系代替专业授权。
- 未提供部门时，复核页显示可修改的默认建议：销售及采购为市场部，行政为综合部，生产/服务实现为生产部，质检/技术为技术部，财务为财务部，体系管理为管理层。可取消不适用过程；默认建议需按实际组织确认。重新复核保留已修改名称及启用状态。
- “下午”等未明确时刻的内容显示建议值，覆盖起点可由上次审核结束日暂带入，均需复核。日历日期跨度与批准审核人日分别处理。
- 时间优先采用通知书明确时刻；缺少时刻时通常建议上午08:30、下午13:00开始，17:00结束，午休12:00–13:00。结合批准人日和独立审核员人数，可将建议调整为08:00开始或17:30结束；不擅自增加批准人日或审核日期。复核页区分通知书原值和建议值，已确认的人工调整会保留。
- 倒班默认不启用，通知书要求或组长勾选时才展开。满足审核窗口条件时，优先建议非末日17:30–18:30，仍需确认实际班次；排不下则提示确认，不自动延长审核日期。新增转场预填可用的30分钟时段，路线与实际耗时须确认。
- 提供海德 A4 纵向审核实施计划预览，包含受审核方信息、审核实施要求、审核组、确认栏和日程。
- 审核日期栏仅列日期；日程按过程、审核要点、涉及部门及各体系条款组织，同义要点合并，专业要点保留。
- 首次会议、内部沟通、管理层沟通和末次会议采用固定用语，每次预留30分钟。非末日内部沟通默认18:30–19:00，末日依次安排内部沟通、管理层沟通和末次会议。
- 日程表中的内部沟通开始时间可直接调整，并可恢复默认；阶段切换保留各自的调整。时间冲突、倒班尚未结束或超出审核起止范围时提示核对。内部沟通沿用现有计入总时长口径，不自动增加批准人日；技术专家和实习人员不计入人日。
- 日程按有效工作时段排满，不再以批准人日作为分配上限。午休、转场及会议占用先扣除，非末日17:00至18:30组内沟通前保留休息间隔。共同任务按全部参与人员的空闲交集安排；人员组合无法排满或缺少主审时，提示具体未排时段，不虚构工作。
- 页面分别展示实际已排人日和批准人日；超过批准值仅作对照提醒，不截断日程，低于批准值仍提示核对。预览、打印与 Word 的总现场审核人日均采用对应阶段的批准值，保持通知书或复核确认值，不用实际日程计算值覆盖；差异在说明中单独列出。
- 在预览中导出 Word，直接填充来源表格的原生模板，保留文件编号、标志及页眉页脚。页数随人员和日程内容自动增加，签字盖章保持空白。
- 支持增强 Excel 的正式认证范围、合同编号、审核准则、联系人、覆盖期间、审核员证书和场所等信息。原始 Sheet1 在第43行起新增补充栏，隐藏 Sheet2 关联读取；旧版导入仍兼容。
- 必要资料、日期或排程存在待确认事项时，暂不启用正式 Word 导出。浏览器预览、打印与 Word 的分页可能因排版引擎不同而变化，正式文档以导出的 Word 为准。
- 追溯日期、联系人、地址、注册号等文件资料可在预排后补齐；仅补资料时保留已调整的分工。批准人日缺失时显示待确认，不以估算值代替。中标联合分体系人日原文单独保留，不未经确认累加为整合后的批准人日。

## 文件与数据

文件在浏览器中读取和处理，应用没有文件上传接口，不把导入的企业资料发送到 GitHub，也不在服务器保存审核计划。页面刷新或关闭后，当前调整会清除。

仓库仅包含程序和运行依赖。默认企业、人员及认证范围为虚构演示数据，不包含实际项目的合同评审表、审核案卷或测试截图。

## 使用范围

自动编排用于形成计划初稿，审核组应核对专业授权、适用条款、审核人日及现场条件。未提供的一阶段日期、批准人日或倒班具体时段会提示确认。倒班排程目前支持审核起止范围内当日 17:00 后的时段。

修改 Excel 后，请完成公式重算并保存，再导入。通知书读取按已接入机构及样本版式适配，不保证任意机构版式均能完整提取。扫描 PDF 需先识别文字或改用 Word，不能将空白识别结果当成完整计划。通知书中的部门职责如未提供，需在复核页补充。旧版配套 Excel 无机构字段时仍默认海德。

中标联合模板保留机构页眉、编号、审核目的、人员栏目、确认栏及日程四列结构。无签名、印章或原项目审批结果；批准意见由授权人员实际填写。同一日期和时段的并行行合并日期/时间单元格，其他时段重复日期以利跨页阅读。末日内部评定与管理层沟通仅在时段相邻且人员一致时合并展示，不改变排程时间。总人日与现场人日分别取通知书或复核值，不用计算时长覆盖。当前模板版本固定保存在项目中，版本不匹配会阻止正式输出。

复核页支持指定人员的单程转场和往返场所审核。每段路途不计审核人日；同一人员的外出安排重叠、路途与午休重叠、外出期间与会议或倒班场所冲突时提示调整。往返可跨日期，但每一段路途须在同一天内；跨日外出仍需满足每日组内沟通的安排。多场所倒班须完整位于对应场所的到达与返程出发之间。旧项目未指定人员的全组转场保留原意，新建安排必须勾选人员。任意跨夜班次和多场所抽样方案的自动决策尚未实现。Excel 的文字场所说明仍需转为结构化安排并由组长核对。MMS、EnMS补充栏仅对应表格保留字段，不表示已接入这些体系的条款和排程规则。

## 本地运行

下载仓库后，可直接用新版 Chrome 或 Edge 打开 `index.html`。PDF 解析需要通过 HTTP 服务访问；使用在线网址即可。

## 维护

这是独立仓库，GitHub Pages 从此仓库的默认分支根目录发布。所有资源使用相对地址，没有自定义域名配置，不改动账号下其他仓库或站点。

`app.js` 为应用逻辑，`audit-rules.js` 为派组规则，`clause-picker.js` 为部门条款选择，`plan-content.js` 为计划用语，`plan-meetings.js` 为会议排程，`plan-scheduler.js` 为满时段任务分配，`plan-travel.js` 为转场及多场所排程，`notice-import.js`、`notice-auditors.js` 与 `notice-review.js` 为通知书解析和复核，`notice-travel-review.js` 为场所及转场设置，`notice-time.js` 为时间建议，`styles.css` 为样式。专业派组策略为应用规则，不代表标准逐条规定审核员资格。第三方依赖说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

`agency-profiles.js` 保存机构配置、检测和输出分派；`agency-review.js` 负责复核页机构选择；`nsi-notice.js`、`nsi-plan.js`、`nsi-template.js` 分别对应中标联合通知书读取、输出字段与浏览器预览、已清理的 Word 母版。机构适配共用现有条款/排程引擎，不把单个项目部门、人员或时间写入公共规则。

`standard-defaults.js` 统一维护 Q/E/S 缺省准则和明确版本的优先级，供通知书、Excel、复核与输出链路共用。
