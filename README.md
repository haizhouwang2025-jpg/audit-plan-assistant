# 审核计划辅助系统

根据参考文件生成管理体系审核计划初稿，支持部门分工、条款拖拽、专业能力检查和日程预览。

## 在线使用

https://haizhouwang2025-jpg.github.io/audit-plan-assistant/

直接打开页面，将审核任务通知书拖入“导入审核任务通知书”区域，或点击选择文件。支持 `.doc`、`.docx`、带文字层的 PDF；系统先打开复核页，确认前不改变原计划。补充实际部门及承担过程、复核专业能力和时间安排后，点击“确认并重排”。

配套 `.xlsx` 仍可从同一入口导入。审核员继续填写原表 `Sheet1`，程序优先读取隐藏的 `Sheet2_小程序读取`。

## 功能

- 支持 QMS、EMS、OHSMS 单体系及其组合。
- 根据 Excel 实际填写的体系范围自动识别单体系、二体系或三体系，联动更新标题、条款、审核员专业选项、覆盖检查及日程。配套表的 Sheet1 实际范围优先于旧隐藏页中固定的 QES 值；空白或“不适用”的范围不计入体系。无法识别时保留原计划并提示，不默认按单Q处理。
- 界面采用海德新版网站的红色标志和主色，体系标签及检查状态保留独立语义颜色。
- 按实际部门合并多个过程，同部门、同体系条款去重。
- 按体系专业能力生成分工建议，支持技术专家共同审核。
- 通过拖动条款卡片调整部门分配，同步更新覆盖检查和日程。
- 分别保留当前页面内的一、二阶段调整。
- EMS 通知书按其中明确的标准版本读取，不自动把 2015 版升级为 2026 版；配套 Excel 保持原有版本选择规则。
- 通知书复核包含项目资料、审核组、部门过程、午休、倒班及全组场所间转场。缺失或有冲突的内容由组长核对，不以演示数据替代。相同实际部门的多个过程会归集。
- “下午”等未明确时刻的内容显示建议值，覆盖起点可由上次审核结束日暂带入，均需复核。日历日期跨度与批准审核人日分别处理。
- 提供海德 A4 纵向审核实施计划预览，包含受审核方信息、审核实施要求、审核组、确认栏和日程。
- 审核日期栏仅列日期；日程按过程、审核要点、涉及部门及各体系条款组织，同义要点合并，专业要点保留。
- 首次会议、内部沟通、管理层沟通和末次会议采用固定用语，每次预留30分钟。非末日内部沟通默认18:30–19:00，末日依次安排内部沟通、管理层沟通和末次会议。
- 日程表中的内部沟通开始时间可直接调整，并可恢复默认；阶段切换保留各自的调整。时间冲突、倒班尚未结束或超出审核起止范围时提示核对。内部沟通沿用现有计入总时长口径，不自动增加批准人日；技术专家和实习人员不计入人日。
- 在预览中导出 Word，直接填充来源表格的原生模板，保留文件编号、标志及页眉页脚。页数随人员和日程内容自动增加，签字盖章保持空白。
- 支持增强 Excel 的正式认证范围、合同编号、审核准则、联系人、覆盖期间、审核员证书和场所等信息。原始 Sheet1 在第43行起新增补充栏，隐藏 Sheet2 关联读取；旧版导入仍兼容。
- 必要资料、日期或排程存在待确认事项时，暂不启用正式 Word 导出。浏览器预览、打印与 Word 的分页可能因排版引擎不同而变化，正式文档以导出的 Word 为准。

## 文件与数据

文件在浏览器中读取和处理，应用没有文件上传接口，不把导入的企业资料发送到 GitHub，也不在服务器保存审核计划。页面刷新或关闭后，当前调整会清除。

仓库仅包含程序和运行依赖。默认企业、人员及认证范围为虚构演示数据，不包含实际项目的合同评审表、审核案卷或测试截图。

## 使用范围

自动编排用于形成计划初稿，审核组应核对专业授权、适用条款、审核人日及现场条件。未提供的一阶段日期、批准人日或倒班具体时段会提示确认。倒班排程目前支持审核起止范围内当日 17:00 后的时段。

修改 Excel 后，请完成公式重算并保存，再导入。通知书读取按海德通知书的字段和审核组表格适配，不保证任意机构版式均能完整提取。扫描 PDF 需先识别文字或改用 Word，不能将空白识别结果当成完整计划。通知书中的部门职责如未提供，需在复核页补充。

复核页中的结构化全组转场时段会从部门审核可用时段扣除，并单列日程，不计审核人日；与会议或倒班重叠、或剩余审核时间不足时提示核对。分组各自转场、任意跨夜班次和多场所抽样分配尚未实现。Excel 的转场文字、多场所和外包现场安排仍保留待确认提醒，不能把未排定的路途时间计为审核时间。MMS、EnMS补充栏仅对应表格保留字段，不表示已接入这些体系的条款和排程规则。

## 本地运行

下载仓库后，可直接用新版 Chrome 或 Edge 打开 `index.html`。PDF 解析需要通过 HTTP 服务访问；使用在线网址即可。

## 维护

这是独立仓库，GitHub Pages 从此仓库的默认分支根目录发布。所有资源使用相对地址，没有自定义域名配置，不改动账号下其他仓库或站点。

`app.js` 为应用逻辑，`audit-rules.js` 为派组规则，`plan-content.js` 为计划用语，`plan-meetings.js` 为会议排程，`plan-travel.js` 为转场避让，`notice-import.js` 与 `notice-review.js` 为通知书解析和复核，`styles.css` 为样式。专业派组策略为应用规则，不代表标准逐条规定审核员资格。第三方依赖说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
